### RAG 离线阶段: 创建向量塞入向量数据库
1、加载数据（Load）：从各种来源（文档、网页、数据库等）加载原始知识。
2、切分数据（Split/Chunk）：将加载的文档切分成更小的、易于处理的文本块。
3、生成嵌入（Embed）：使用 `Embedding 模型`为每个文本块生成`向量嵌入`。
4、存储入库（Store）：将文本块及其向量嵌入存储到向量数据库中，并`建立索引`。

### RAG 在线阶段：用户查询与生成
1. 用户提问（User Query）：用户输入一个问题或指令。
2. 查询嵌入（Query Embedding）：将用户的问题也转换成一个查询向量。
3. 检索（Retrieve）：用查询向量去`向量数据库`中`搜索最相似`的 Top-K 个文本块（这些就是 “查到的资料”）。
* rag设置了阈值之后,是否相似度低于阈值就不会返回,并且不会嵌入llm prompt中了
4. 增强与生成（Augment & Generate）：

* 将用户`原始问题`和检索到的相关文本块一起`组织成一个新的提示（Prompt）`给到 LLM。
LLM 参考提供的资料和自身知识，生成最终的答案。

## RAG 的关键技术要点
1. 数据预处理与切块（Chunking Strategy）：
    1. 切多大？太小可能丢失上下文，太大可能引入无关噪声或超出 LLM 上下文窗口。
    2. 怎么切？按固定字数、按句子/段落、基于语义的智能切分。
    3. 元数据（Metadata）：为每个块附加有用的元数据（来源、标题、日期等）可以帮助后续的过滤和引用。
2. 嵌入模型选择（Embedding Model Quality）：
    1. 质量至上：Embedding 的质量直接决定了检索的准确性。“垃圾进，垃圾出”。
    2. 一致性：`查询和文档必须使用相同的 Embedding 模型`。
    3. 领域适应性：如果你的知识库非常专业，通用的 Embedding 模型可能效果不好，有时需要微调或选择领域特定的模型。
3. 检索策略（Retrieval Strategy）：
    1. Top-K 选择：检索多少个相关的文本块？太少可能信息不足，太多可能引入噪声或超出 LLM 上下文长度。
    2. 相似度阈值：只选择相似度高于某个分数的块。
    3. 混合检索（Hybrid Search）：结合向量相似度搜索和传统的关键词搜索，有时效果更好。
    4. `重排（Re-ranking）`：对初步检索到的 Top-K 结果，`用更复杂的模型（如 Cross-Encoder）进行二次排序`，高最相关结果的排序。

4. 上下文构建与提示工程（Context Construction & Prompt Engineering）：
    1. 如何组织：怎么把用户问题和检索到的多个文本块有效地组合成一个清晰、简洁的提示给 LLM？
    2. 指令清晰：明确告诉 LLM 它的任务是“根据以下提供的上下文信息来回答用户的问题”。
    3. 处理超长上下文：如果检索到的内容太多，如何筛选、压缩或分批喂给 LLM？
    * `例如一个人来到餐厅点菜,瞎扯了一小时才说要吃回锅肉,那么就得前台服务员筛选一下,才把有价值的话传给厨师(一份回锅肉)`
    4. 处理冲突信息：如果检索到的不同文本块之间有矛盾，LLM 如何处理？（可以在提示中引导）
5. 生成模型选择（Generation LLM Choice）：
    1. 选择一个理解能力强、遵循指令能力好、幻觉少的 LLM 作为生成器。
    2. LLM 的上下文窗口大小也会影响你能喂给它多少检索到的信息。
6. 评估与迭代（Evaluation & Iteration）：
    1. 如何评价 RAG 系统的好坏？
        1. 检索质量：召回率（Recall）、精确率（Precision）、MRR（Mean Reciprocal Rank）等。
        2. 生成质量：答案的相关性、准确性、流畅性、是否有害。
        3. 端到端评估：结合具体业务场景的综合评估。
    2. 持续监控、分析 bad case、不断优化上述各个环节。

### recall召回率
* 在 RAG（检索增强生成）系统中，召回率（Recall）是用于评估检索模块性能的重要指标，它衡量的是检索系统在给定查询下，能够正确检索出相关文档或文本块的能力

* 假设用户提出一个查询问题，在 RAG 系统的知识库中，实际上与该查询`真正相关的文本块有 100 个`（这是文档集合中所有的相关文档数） 。经过 RAG 系统的检索模块运行后`，成功检索出了 80 个`与该查询相关的文本块（这是检索出的相关文档数） 。

根据上述召回率公式计算可得：`Recall = 80/100 = 80%`
